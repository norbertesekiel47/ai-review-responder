## `src/lib/`

### `solicitation/` (continued)

| `dispatch.ts` | **(#899)** The deep module behind `solicitation_send` — one job, one **Outreach row**. Two doors: `applyDispatchGate` (PURE; the single owner of amendment B6's seven-item ORDER and of the withheld-reason mapping — walk in order, return the FIRST failure; `batch_open` and `send_flag` are the only two DEFER items, everything after them terminalizes) and `dispatchOutreach` (the orchestrator). Traps: (a) the gate is per-CHILD and therefore per-CONTACT — an account-level fact (subscription, daily cap, the **Send breaker**) belongs to #900's release poller, never to an item here; (b) `postal_address` is ONE item with TWO reasons, absent vs present-but-mismatched, and only the mapping tells the owner which to fix; (c) `send_flag` off is a **defer**, not a withhold — 091/110 carry no `flag_off` reason and inventing one would terminalize a row the owner never withdrew (decision 5); (d) nothing in this lane logs the rendered subject, the rendered body, the recipient handle or a raw token — `createWorkerLogger` sanitizes object args only. **Shape: TWO transactions with one provider call between them.** tx1 (`runDispatchTx`) opens with the stale-attempt guard, then the advisory lock, then the batch and Outreach rows `FOR UPDATE`; only a `queued` row is dispatchable; it PROVES the locked bytes are the ones the unlocked slow gather linted and moderated (`digestEvaluatedBytes`), gathers the five fast items, applies the gate, and on a pass mints the unsubscribe token, creates the **Lazy child**, CASes `queued → sending` and assembles the outbound envelope. `sendWithBoundedRetry` then reaches the **Messaging adapter** with NO lock held. tx2 (`commitSendTerminal`) commits the terminal facts as one unit; if it does not commit, the outbox attempt does not either, so the watchdog still owns the work (D12a) and this lane needs no orphan sweeper. **(#1010)** `commitWithhold` also writes the Refusal ledger's `outreach_withheld` DISPATCH lane on tx1 — one row against the OUTREACH id (never the ask, which is `ask_withheld`'s subject), placed LAST so a ledger failure rolls back the withheld terminal, the Lazy child, the receipt step, the outbox completion and the settlement join together; a DEFER writes nothing, because a defer is a no-decision. `occurredAt` is the GATE's own `now`, threaded in from `runDispatchTx` as `decidedAt` and never the `'transaction_time'` sentinel: tx1 takes the advisory lock and two row locks before the gate runs, so the sentinel would stamp a decision measurably before it was made. The map is `OUTREACH_WITHHELD_DISPATCH_REFUSAL_CATEGORIES` and never the render half, which is a different writer over a different enum (#1011). Four more traps: (e) `provider_message_id` persists on the terminal CAS, so when that CAS matches NO row **nothing about the send may be committed** — no `solicitation_sent` outcome, no `ask_sent` step, no child terminal and no `closeBatchIfSettled`; only the outbox attempt is settled, because an outcome without its join key makes every later bounce, complaint and opt-out unattributable and a **Settled batch** joined twice is a duplicate receipt; (f) BOTH defer paths — the flag-off short-circuit above tx1 and the gate's own `batch_open`/`send_flag` items — record a `dispatch_gate_evaluated` step on the **Send batch parent**, never a **Lazy child** (a defer never dispatches), and best-effort so a missing parent defers quietly instead of failing the job; (g) the raw token lives only in this module's memory, so a fresh process that finds the row already `sending` — or its token row already minted — can rebuild no correct body and must neither re-send nor re-GATE (recording `withheld` for a message that may have reached a real person is the lie `unknown` exists to avoid); (h) `completeOutboxNoop` is a deliberate second copy of `ask-generation.ts`'s, whose real owner is `src/lib/shared/outbox.ts` — it must not become an export of `ask-generation.ts`, whose module graph drags the LLM task seam and the cost guard into this lane. Injected `Sql` (invariant #15). |

| `suppression.ts` | **(#643; §7.4 display seam #645)** The **Suppression ledger**'s domain core. Closed `SUPPRESSION_SOURCES` / `SUPPRESSION_SCOPES` / `SUPPRESSION_CHANNELS` `as const` arrays (never string literals at call sites); `recordSuppression` (first-write-wins `ON CONFLICT … DO NOTHING` against the two partial unique indexes, each predicate re-spelled byte-for-byte, with the `solicitation_suppressed` analytics insert in the same tx); and `suppressionMatchSql`, the ONE owner of the §1.2 lookup (G7 — no `isSuppressed()` helper), composed by callers into a `LEFT JOIN LATERAL`. **#645** adds `scope` to that projection — §7.4 needs an owner surface to tell its own reversible `account` row from a `global` one, and deriving it caller-side from `source === 'owner_manual'` would be correct only until a second account-scoped source existed — plus the read seam `toSuppressionDisplay` + `SUPPRESSION_DISPLAY_COPY` (#629 consumes the same one).
