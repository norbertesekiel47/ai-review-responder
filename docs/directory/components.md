## `src/components/`

Reusable React components imported by multiple pages.

- Component placement convention: see `docs/src-structure-preferences.md` → "Component placement rule".

| File | What it does |
|------|--------------|
| `DashboardContent.tsx` | Top-level owner dashboard shell. Composes sub-components (`ReviewsList`, `Charts`, `ValueSummary`, `ConnectGoogleBanner`, etc.) and passes dashboard data down. |
| `OwnerNav.tsx` | Top nav bar for the owner dashboard (logo, business name, settings link, logout). |
| `PlaceAutocomplete.tsx` | Google Places autocomplete input (uses `PlaceAutocompleteElement`; guarded for SSR with `typeof window !== 'undefined'`). |
| `admin/ImpersonationBanner.tsx` | Sticky high-contrast strip at the top of `<main>` while `loadAdminShellContext` reports a live view-as session — account label, `ends HH:MM:SS UTC`, and an inline `EndImpersonationButton`. |
| `admin/EndImpersonationButton.tsx` | Ends the current session via `/api/admin/impersonation/end`, then full document navigation with `window.location.assign(adminAppUrl)` to the trusted Admin home. `tone` and `compact` variants serve the view page and banner. |
| `admin/nav-config.ts` | Remaining Growth/Support breadcrumb root and `ADMIN_AUTH_ROUTES` for the three bare auth pages. Filesystem parity is pinned by `__tests__/nav-config.test.ts`. |
| `admin/AdminShellFrame.tsx` | Bare children on login/forgot/reset; otherwise the minimal legacy header, one plain Open Admin app link from the trusted server prop, and main content with the live impersonation banner. Owns viewport height and background; no sidebar or nav-counts polling. |
| `admin/AdminIdentity.tsx` | Header identity, AAL2 state and local MFA Verify link, plus the preserved Supabase sign-out flow to `/admin/login` with visible failure and retry. |
| `admin/ui/AdminPage.tsx` | Retained impersonation page chrome: Growth/Support breadcrumb, title/description, optional actions, and `max-w-7xl` measure. Forms use `max-w-2xl`; data uses the full measure. |
| `admin/ui/DataTable.tsx` | Generic sortable table primitive with two paging modes, plus the exported `PaginationFooter` + `serverPaginationFooterState` for consistent "Showing a–b of N" text and dead-end guards. Optional per-row "View →" link column. In server mode it pushes its display clamp back to the caller, so a caller stranded past a shrunk `totalRows` converges instead of refetching an empty page. |
| `admin/ui/format.ts` | The console's single date/number formatter — `formatAdminDateTime` (self-labels " UTC"), `formatAdminDate` (bare; caller labels the zone), `formatAdminTime` (`HH:MM:SS UTC`, for the live-data provenance line and the view-as banner), `formatAdminCount`. All pinned to locale `en-US` + `timeZone: 'UTC'`, because admin pages now render on Vercel (UTC) *and* in the browser (the admin's zone and locale) and a runtime-derived `toLocale*` mismatches on every hydration. `__tests__/format.test.ts` bans `toLocale*` and un-zoned `Intl.DateTimeFormat` across `src/app/admin/**` + `src/components/admin/**`. |
| `admin/ui/states.tsx` | `EmptyState`/`ErrorState`/`TableSkeleton` primitives for admin list/detail pages. |
| `auth/LoginFormClient.tsx` | Login form (email + password → Supabase sign-in). |
| `auth/ForgotPasswordFormClient.tsx` | Forgot-password form. |
| `auth/ResetPasswordFormClient.tsx` | Reset-password form. |
| `auth/useRecoveryStepUp.ts` | Headless MFA step-up for password recovery: probes the recovery session + verified factors, then challenges/verifies via `/api/auth/mfa/challenge` so the session is AAL2 before the password write. Consumed by both reset cards. |
| `auth/RecoveryStepUpField.tsx` | Presentational TOTP code field (plus factor picker when >1) shown inline on the reset cards. Styling arrives via className props. |
| `dashboard/AccountStateScreens.tsx` | Full-page states for non-active accounts (pending payment, cancelled, past-due). |
| `dashboard/Charts.tsx` | Recharts-based charts for the owner dashboard (response rate, star distribution, etc.). |
| `dashboard/charts/` | Shared chart primitives: measured-viewBox contract (`useMeasuredSvg`), d3-backed `VelocityChart`, hover/tooltip/motion presets, chart tokens. |
| `dashboard/charts/CardViewTabs.tsx` | The in-card view switch — real `tablist`/`tab`/`tabpanel` semantics with roving focus, for a control that swaps a panel WITHOUT leaving the page. Two callers (`AggregateVelocityCard`, `AggregateRankingCard`), each of which previously shipped its own inline-styled pair of `aria-pressed` buttons — which announces "two toggles", not "one of these two". Route-level switches (`ReviewsTabs`, the settings rail) are deliberately NOT this: they navigate, so they stay `<nav>` + `aria-current`. |
| `dashboard/kpi/WeeklyRecapCard.tsx` | **"Your week"** — the glance dashboard's zone 2 (Source B rules 22–23), a flat Harbor card between the hero row and the agent team. Renders `computeWeeklyRecap`: the conclusion as a sentence, two stats, the weekly counts as bars, and the in-place "why" line. The Insights brief is OPTIONAL enrichment capped at three bullets — the card must be complete without it, because a new account has none. Returns `null` only when there is no series at all; a series of zeros renders as designed content. |
| `dashboard/shell/AccountMenu.tsx` | The account control at the top of the sidebar rail: avatar, owner name, `chevron-updown`, opening a popover with Profile / Plan and billing / Security / Sign out. Owns the sign-out call and reports its failure as an error toast (the owner stays signed in). `compact` renders the avatar-only trigger for the mobile top bar — below 768px the sidebar is hidden, so this is the ONLY route to sign out. |
| `dashboard/shell/useMenuPopover.ts` | Single owner of Console popover-menu behavior: open/close, outside-click dismissal, Escape with focus restored to the trigger, Tab to close, and roving Arrow/Home/End over any `menuitem` role. Two callers — `LocationPicker` and `AccountMenu`. Items are discovered from the DOM, not registered, so a menu can mix links, buttons, and radios. `close` (leave focus) and `closeAndRestoreFocus` are distinct on purpose: a navigating item must not have focus yanked back mid-route-change. |
| `dashboard/shell/toast/` | The Console's one confirmation surface. `ToastProvider` owns the queue, per-tone dismissal timing (an error lives twice as long as a confirmation) and timer teardown; `ToastRegion` renders it. Both arms ship together by rule — `success`/`info` are polite `role="status"`, `error` is assertive `role="alert"`, each with an icon so the outcome survives without colour. Hand-rolled and rendered in-tree: a portal would leave `.rw-console` and strip every scoped token. Replaced the settings-only `.saved-toast` pill, which had no failure arm. |
| `dashboard/ConnectGoogleBanner.tsx` | Banner surfacing the owner's Zernio GBP connection state. States: active (hidden), none (blue CTA), disconnected (orange CTA), finalize_unknown (yellow ops-alert). |
| `dashboard/account-state/ImportOfferBanner.tsx` | **(#677)** The **Import offer** prompt, a new adapter at the existing banner seam beside `ConnectGoogleBanner` (same `banner` / `b-title` / `banner-cta` anatomy; self-nulls on `{ state: 'none' }`). Sources state from `GET /api/dashboard/import-offer`, **not** the Redis-cached dashboard payload, so a declined offer stops rendering immediately. Carries `offer → importing → outcome → gone`, polls only while `importing`, advances only on a successful POST (never optimistically), and shows no retry on `failed` — retry is the worker's via the `completed_at IS NULL` sentinel. Query key includes the scoped `locationId` so one location's offer can never render against another. Copy is locked verbatim, incl. the 7-day disclosure and the reassurance line. |
| `dashboard/ComingSoonChannelRow.tsx` | Placeholder row for channels not yet available to owners (WhatsApp only). |
| `dashboard/reviews/PastReplyCard.tsx` | Card for one row of the **Reviews list**. Renders the server-derived `reply_state` + Action slot `row_action` (#727, via the shared `ReplyPanel`) — it never computes an affordance — so every "never offer Generate on X" rule lives in `replies-view.ts`; a moderation-held replacement arrives as `row_action 'none'`, never as a held value. Shows the review on the left, the reply (when any) on the right, and a `ProvenanceBadge`. Mutation affordances (`Regenerate` → `EditReplyDrawer`, recovery) appear only when `editRepliesEnabled` is passed true. A missing regen-budget map entry means **unknown**, not zero: `Regenerate` stays enabled and the counter hides (fail-open, per the cost-guard matrix). |
| `dashboard/reviews/InlineGeneratePanel.tsx` | **(#678)** The `Generate` door's inline expansion on a never-replied row — the low-risk counterpart to `EditReplyDrawer` (which replaces a LIVE Google reply and therefore stays a two-pane drawer). Presentational; all fetch/poll/state lives in `useInlineGenerate.ts`. |
| `dashboard/reviews/useInlineGenerate.ts` | **(#678)** Hook owning the inline Generate lifecycle: POST `reviews/[reviewId]/generate`, then poll `reviews/[reviewId]/draft-status` until `ready` or terminal, mapping the route's closed error strings to owner-facing copy. |
| `dashboard/reviews/client-helpers.ts` | **(#765)** Browser-safe JSON parsing plus the shared 1500ms cadence / 60-second Reply polling budget. The two poll state machines remain separate. |
| `dashboard/AgentTeamStrip.tsx` | **(WS5)** Three-card Reply/Guardian/Insights summary strip. Follows the dashboard's account/location scope and time window; zero-count agents remain visible as "Standing by". |
| `dashboard/NeedsAttentionList.tsx` | **(WS5)** Owner exception queue backed by `/api/dashboard/escalations`; hidden when empty, otherwise links each open escalation to its review timeline. |
| `dashboard/timeline/` | **(WS5)** Timeline presentation package: `TimelineContent`, `RunTimeline`, `TimelineStepRow`, `RunStateBadge`, and `TimelineEscalationActions`. Renders stored persona attribution and structured facts; acknowledge/resolve actions reuse the existing Guardian transition routes. |
| `dashboard/OwnerTelegramWidget.tsx` | Owner-facing Telegram enrollment widget. Uses `useEnrollment` + `enrollmentReducer`; SSR-hydrated from server-loaded enrollment row. |
| `dashboard/ReviewActions.tsx` | Approve / Edit / Regenerate action buttons for a single review. |
| `dashboard/ReviewsList.tsx` | List of reviews with inline response drafts and action buttons. |
| `dashboard/settings/SettingsSidebar.tsx` | Grouped settings nav — vertical sidebar (desktop) / native `<select>` with `<optgroup>` (mobile ≤768px); active item from `usePathname()`. Rendered once by `settings/layout.tsx`. |
| `dashboard/settings/SolicitationAddressPanel.tsx` | **(#656)** The owner-facing **Attested postal address** surface on `/settings/profile` — a **sibling** of `ProfilePanel`, never an edit to it (deviations D3), rendered FIRST so the delete-data danger zone that `ProfilePanel` itself contains stays terminal. Its state arrives as a prop the server component already fetched for the cookie-resolved active location, so nothing widens the shared `/api/settings` payload or `useSettingsForm` for one panel's data. Three load-bearing behaviours: `google_place_address` is an editable **suggestion** that never submits itself; submitting requires the attestation checkbox, whose label is `POSTAL_ADDRESS_ATTESTATION_TEXT` imported from the domain module (a hand-copied string would let the stored compliance record drift from what the owner agreed to); and editing **clears** the checkbox, the UI half of migration 099's digest CHECK. Writes go to `PUT /api/settings/postal-address`; lint reasons render as returned, never re-derived. |
| `dashboard/ValueSummary.tsx` | Value-at-a-glance metrics strip (e.g. responses sent, approval rate). |
| `legal/LegalPage.tsx` | **(Wave 1)** Shared renderer for every `/legal/*` page. Takes a `LegalDoc` from `src/lib/legal/content.ts` and renders its title, version + effective date, and sections (prose / bullets / table). |
| `ui/useDisclosurePopover.ts` | **(#1086 follow-up)** What every Console popover shares, and nothing more: open state, stable ids, outside-**pointer** dismissal, and close-with-focus-restored. Two consumers — `dashboard/shell/useMenuPopover.ts` layers the menu behaviour on top (open-focus, ArrowDown/Up on the trigger, roving Arrow/Home/End), and `ui/InfoTip.tsx` uses the core directly. **Three traps.** (a) The split is load-bearing, not tidiness: the menu hook `preventDefault`s Arrow/Home/End **before** checking whether an item exists, which is right for a menu and would swallow arrow-key page scrolling for a tip. Do not move that handler down here. (b) It listens on **`pointerdown`**, not `mousedown` — iOS Safari synthesises no mouse event for a tap on a plain `<div>`, so a menu with a `mousedown` listener would not dismiss on an outside tap. (c) `panelIdSegment` defaults to `panel`; `useMenuPopover` passes `menu` so its ids stay byte-identical to the ones it minted before this seam existed — an id is a public surface once it is in `aria-controls`. `openPopover` takes no argument on purpose: the menu's focus-target choice belongs to the menu layer, and `useMenuPopover` keeps its own `toggle` for exactly that reason. |
| `ui/InfoTip.tsx` | **(#1086)** The dashboard's one "what does this number mean" affordance — a trigger beside a headline that reveals short copy. Hover previews it only where `useMediaQuery('(hover: hover) and (pointer: fine)')` reports a real pointer (the repo's one hover predicate), a click or tap pins it everywhere, `Escape` closes and returns focus; `aria-describedby` is set **only while open**, so the reference never points at a node outside the a11y tree. Hover handlers live on the CONTAINER, never the trigger — an 8px gap sits between them, and button-only handlers made hover-revealed content vanish as you reached for it (WCAG 1.4.13). Outside-dismissal listens on **`pointerdown`**, not `mousedown`: iOS Safari synthesises no mouse event for a tap on a plain div. **Four traps.** (a) It does **not** use `useMenuPopover`, which preventDefaults Arrow/Home/End before checking whether a `menuitem` exists — a tip has none, so reuse would swallow arrow-key page scrolling, and it would be the first `components/ui/` → `components/dashboard/` import; a test pins the arrow keys. It shares the half that IS common through `ui/useDisclosurePopover.ts`, which the menu hook also builds on — so there is one owner for dismissal and one for menus. (b) Both elements are `<span>`s, so a tip is legal inside a heading OR a label. Where the host has an `<h2>` the tip goes **beside** it, never inside — those sections are `aria-labelledby` that `<h2>`, and a trigger within it joins the card's accessible name. `ReputationHeroBand` has no heading at all: its two tips sit **inside** `<span class="rep-stat-label">`, which is correct there. Four host shapes exist — new wrapper + flex class (`NeedsAttentionList`), `margin-inline-end: auto` against a `space-between` row (`RepPulseCard`), the shared `.card-h2-row` (`WeeklyRecapCard`), and nested in a label span (`ReputationHeroBand`); pick by what the host already is. (c) **A tip in the RIGHT part of a wide row must pass `align="end"`.** The 18rem panel is anchored to its trigger, so a `start`-aligned right-hand tip runs past the canvas and `.main { overflow: clip }` cuts it with no scrollbar — measured at 897px inside a 769px viewport, still overflowing at 1000px. Screenshots at 390px and 1440px straddle that band and see nothing. (d) Copy lives at the call site, and where it states a number it reads the constant (`MINUTES_SAVED_PER_RESPONSE`, `REP_PULSE_WEIGHTS`) so it cannot drift from the arithmetic — and it must be checked against the QUERY, not the label: three of the five shipped copies were factually wrong at review (wrong time anchor, a hardcoded window on a component that also renders under a window selector, and an unconditional weight split the score renormalises away). **When a tip is warranted:** only when a better label or an existing sentence will not do — `PendingApprovalsStrip`, `AgentTeamStrip` and the grid's Response rate deliberately carry none, each pinned by a structural test. **Seven tips across five surfaces**: four on the per-location dashboard (`ReputationHeroBand` ×2, `RepPulseCard`, `WeeklyRecapCard`), one shared with the aggregate (`NeedsAttentionList`), and two on `ValueKpiGrid`, which is the AGGREGATE scope's headline row and also renders on aggregate analytics. **The aggregate's numbers are LIFETIME** (`total_responded_all_time`) while the hero's same-named "Time saved" is windowed — the same word over a different metric, which is why its copy is written separately and must never be copied across. Styling is Console-only (`console.css` § Info tip), with on-hero and on-deep-panel ink AND focus-ring overrides (`--rw-focus` is 1.44:1 on the deep panel) and a `max-width: 768px` rule that spans its gutters. |
