## Axis questions — direct answers

**Q1 — Is the CSS correct and idiomatic?** Mostly yes; token discipline is clean.

- **Tokens:** every one of the 23 `var(--rw-*)` references in the new block resolves in `tokens.css` (checked individually). No hex literal, no amber/orange/stone, no ad-hoc colour. `--rw-radius-core`, `--rw-shadow-pop`, `--rw-dur-fast`/`--rw-ease` are the enumerated Console values. The one token gap is the focus ring on the inverted surface — **M4**.
- **Literals:** `font-size: 12px`, `20px`/`14px` box sizes, `z-index: 20`, `line-height: 1.5` are **not** violations. `console.css` at this SHA already contains 145 `font-size: <n>px` declarations and eight bare `z-index` integers; DESIGN.md's literal ban is specifically "Don't write a literal hex in a component" (line 632). Consistent with the file.
- **Reduced motion / coarse pointer:** structurally consistent with the file — both entries were appended to the existing blocks rather than opening new ones, and the coarse-pointer comment correctly explains why the trigger cannot join the `min-height: 44px` list. One of the two reduced-motion entries is dead — **M7**.
- **The `max-width: 768px` override is sound horizontally.** I walked the ancestor chain (`.info-tip` → `.rep-stat-label`/`.needs-attention-title` → `.rep-stat`/`div` → `.rep-stats`/`.needs-attention-head` → `.card`/`.rep-hero`/`.needs-attention` → `.content--dash` → `.main`): **none** sets `position`, `transform`, `filter` or `contain`, so the containing block genuinely becomes the initial containing block and `left/right: var(--rw-sp-4)` genuinely spans the viewport gutters. `.main { overflow: clip }` (486) does **not** clip it, because an abspos box whose containing block is an ancestor of the clipping box escapes the clip. The comment's claim is correct as written.
- **`top: auto` + `margin-top` is workable but fragile, and the comment misdescribes it** — **M11**.
- **Specificity and ordering are correct.** The two surface overrides (3064, 3073, both `(0,2,0)`) are declared *after* `.info-tip-trigger:hover` (2997, also `(0,2,0)`), and each ships its own `(0,3,0)` `:hover` companion, so the cascade resolves as intended in both directions. The mobile block (3038) precedes the surface overrides, none of which touch `position`.
- **`.pulse-head .info-tip { margin-inline-end: auto }` is the right fix, not a workaround.** `.pulse-head` is `display:flex; justify-content: space-between` with three children; the auto margin is the canonical flexbox idiom for "group the first two left, pin the third right" and avoids a wrapper element. It masks no layout problem. It is, however, the second of four mechanisms — **M13**.

**Q2 — Is `InfoTip.tsx` well-shaped?** Structurally yes; three defects (M1, M2, M3, M5) and two non-issues:

- **`requestAnimationFrame` after unmount is harmless.** `closeAndRestoreFocus` (87-90) schedules no cancellation, but the callback is `triggerRef.current?.focus()` and React nulls the ref on unmount, so the late frame is a no-op. It also matches the repo precedent exactly (`useMenuPopover.ts:65-68`, which likewise does not cancel this particular frame while it *does* cancel its open-focus frame at 93). Not a finding.
- **The two `useState`s are correct as two.** `open = pinned || (hasHover && hovering)` (80) is a clean derivation of two genuinely independent inputs; collapsing them would need a three-state enum plus a rule for what a `mouseleave` does to a pinned tip, and would read worse.
- **No stuck or wrong state found.** I traced: hover→leave; hover→click(pin)→leave (stays open, test-covered); pin→click(unpin) with the pointer still over the trigger (closes and stays closed until the pointer re-enters — intended, since `hovering` was cleared); outside-mousedown while hovering; Tab-onto-trigger while hover-open; `hasHover` flipping mid-hover. The last two leave the tip closed with a stale `hovering: false`, which is the safe direction. The only *behavioural* gap is that the panel is unreachable by pointer — M1.

**Q3 — Duplication and single-owner discipline.** Two real owners are missing (M2 hover detection, M3 dismissal). `PulseTip` in `RepPulseCard.tsx:34-42` is **correctly** shaped — it has two render branches (58 and 97), so it is not an abstraction for a single caller, and the deviations doc records that a `replace_all` originally reached only one of them, which is precisely the bug a named component prevents. Id generation and panel lookup are consistent: every call site and test resolves the panel through `trigger.getAttribute('aria-controls')` rather than a class or a nth-child.

**Q4 — Test quality.** The four identically-titled tests are a **smell, but a mild one, and not the one to fix.** Four suites carrying the string `every covered surface names what its number means` produce four rows in the vitest report that are indistinguishable, and each one covers exactly **one** surface, so the title over-claims at every site. More importantly the "every" is enforced nowhere — a sixth surface can gain a tip with no test and nothing goes red. If the contract must match a fixed string, the honest shape is one title per site (`… names what "Rep Pulse" means`) plus one enumerating test that asserts the *set* of tip triggers rendered by `DashboardContent`. Brittleness beyond that: M9 (negative assertions that cannot fail), M10 (hardcoded arithmetic), M8 (`nextElementSibling`). The copy assertions (`'Guardian reads every review'`, `'not your all-time rating on Google'`, `'the week it was written'`) are exact-substring matches against prose that lives inline in the components; the same branch shows the alternative by importing `RESPONSE_RATE_PERIOD_CONTEXT` at `ReputationHeroBand.test.tsx:6`, and the repo already keeps dashboard copy in modules (`response-rate-copy.ts`, `brief-bullets.ts`). Not raised as a separate finding because five short sentences do not yet justify a copy module — but the asymmetry inside one branch is worth noting.

**Q5 — Complexity gate: no risk. The invariant holds.** I read every added line in the four touched components: there is **not one new conditional, ternary, `&&` guard, loop or early return**. Every addition is JSX plus one new zero-branch function (`PulseTip`), which is rendered by both existing branches and directly covered by `RepPulseCard.test.tsx:120-133` and `:135`.
