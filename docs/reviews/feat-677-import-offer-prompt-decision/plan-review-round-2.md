## Defects introduced by fixes

| Severity | Location | Defect | Recommendation |
|---|---|---|---|
| High | T1/T4 `createImportOffer` and GET self-heal | The helper contract guards only `pending + NULL`; it does not atomically prove both subscription activation and a current active connection with non-NULL `connected_at`. PostgreSQL `GREATEST(NULL, x)` returns `x`, so a one-sided location can get an offer before the junction; both NULLs can produce a NULL-to-NULL update reported as created. | Make junction eligibility part of `createImportOffer`'s SQL: require non-NULL activation, an active connection, and non-NULL connection anchor. Add live negative tests for each missing half and both missing. |
| High | T1/T3/T4 deadline anchor | `connected_at` is mutable on repeated finalize (`finalize-tx.ts:123-132`), despite migration 026 describing it as first-active time (`026_zernio_publishing.sql:85-87`). If the first offer write fails, a reconnect before self-heal moves the anchor and restarts/extends the seven-day window, contradicting position independence. | Preserve an immutable first-connection/junction anchor and calculate every repair from it. Add “missed creation, reconnect, then self-heal keeps the original deadline.” |
| High | T1/T3 all enqueue producers | `WHERE NOT EXISTS` dedup has a check-then-insert race across concurrent producers. The worker's run-row conflict avoids duplicate execution state but does not enforce the promised one-outbox-row contract. | Add a partial unique index with matching `ON CONFLICT`, or serialize every producer on the same business lock. Add a live concurrent cross-producer test. |
| High | T3 reactivation versus an already-dispatched worker | The new in-flight check can lose accepted-but-incomplete recovery: a worker can read `archived_at`, reactivation can unarchive and skip enqueue because that old row is still `dispatched`, then the worker completes the old row from its stale archived read (`job-eligibility.ts:60-81`). The result is `completed_at IS NULL` with no job and no automatic trigger. | Serialize the eligibility read/skip completion with reactivation, or atomically replace/supersede the stale in-flight row. Add this race as a live integration test. |
| High | T3 reactivation completed-run predicate | Applying the generic “no completed run” condition to reactivation can suppress the existing archived-period catch-up after an accepted location already completed its initial or a previous reactivation run. Current code deliberately gives reactivation its own `run_reason` and correlation identity (`ZernioBackfillWorker.ts:139-170`). | Preserve reactivation-specific retry/idempotency semantics; do not use a broad historical completed-run sentinel. Test accepted reactivation after a completed initial run and after an earlier completed reactivation. |
| Medium | T1 zero-row outcome classification | A concurrent NULL-to-live self-heal between guarded update and re-read yields `pending` with a future deadline, which the stated classifier falls through to `already_answered`. | Explicitly handle live-pending on re-read by retrying the guarded transition or returning a deliberately defined retryable outcome; add the concurrent live-DB case. |
| Medium | T3/T4 transaction ownership | Stripe and GET are instructed to call a `TransactionSql` helper without a specified transaction. This leaves F107 unresolved and makes atomic offer/analytics/enqueue behavior implementation-dependent. | Define domain wrappers that own `sql.begin`; keep routes/ingress as one-call orchestrators. |
| Medium | T2 lineage fallback | Selecting the lineage key only from the new row misses a new canonical Place-ID row against an unresolved archived URL row for the same place. | Match canonical IDs when both are present, otherwise fall back to a non-NULL Maps URL equality; pin both cross-mode directions. |
| Medium | T4/T5 revised eval | The live view suite omits positive-complete/pending SQL, and the banner suite omits positive imported rendering and `LiveRegion`. The claimed F108/F110 closure can pass with those paths wrong. | Add the missing live view and component assertions; title 55 must explicitly mention the accessibility announcement if it owns it. |
| Low | Intake precedent and T4 analytics | `intake:69` now misstates the draft route as a thin domain-call precedent. Separately, T4 self-heal does not say to emit `import_offer_created`, so the only successful creation after a Stripe failure can disappear from the promised analytics ratio (`plan:323-329`; `intake:165-167`). | Cite only the draft route's real CSRF/scope/zod traits or choose a true thin-route precedent; emit analytics in the same self-heal transaction or make creation own it. |
