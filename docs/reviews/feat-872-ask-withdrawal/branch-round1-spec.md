## Low-confidence appendix

- Intake `user_visible_behavior[0]` says "every listed row shows a `Withdraw` control"; the implementation (and plan Task 4, and test `:1047`) renders it only on `rendered`/`queued` rows — withheld/sending/sent rows are listed without a control. This is the only reading that doesn't offer a button that can only 409; I treated it as the plan refining the intake, not drift. Worth one line in the intake at step 8 if the orchestrator wants the two documents byte-consistent.
- Local test DB drift: at 02:27 the DB at `TEST_DATABASE_POOL_URL` (`test_ws4`) was at head 108 (the gate log shows it was provisioned to 109 at 02:16 — a sibling worktree's `pnpm test:db:setup` reset it in between). To run the suite under review I applied `109_outreach_owner_withdrawn_disposition.sql` with psql (additive, idempotent, superset — cannot break a sibling's 108-head suites). Not a code finding; flagging so the orchestrator knows the shared DB is being rebuilt by more than one worktree.
- `isWithdrawableState` is exported "so the panel … can share the predicate" (`approval.ts:709-714`), but the panel derives withdrawability from `panelMode`'s `haltable` arm, not from this export. Design/style territory (another agent); noted only because the docblock names a consumer that does not exist.
- `LANE_REFUSAL_COPY.not_withdrawable` is one sentence for halted/closed/expired and discards the wire's `state`, unlike `NOT_REGENERABLE_COPY`. Intake only mandates the wire; a stale tab reading "This message can no longer be withdrawn" on a halted batch is not false. Design choice.
- Keyboard focus after the first tap: the resting Withdraw button unmounts and the Confirm/Keep pair mounts (`AskList.tsx:307-341`), so focus drops to `body`; a keyboard owner must re-tab to Confirm. Not spec; a11y polish.
- The armed `<span role="group">` has no accessible name; ARIA does not require one for `group`, but a `aria-label` naming the contact would help screen readers.
- Confirm's accessible name is `Confirm: withdraw the message to X` while the visible label is `Withdraw` — Label-in-Name is satisfied case-insensitively; a strict tool may prefer the visible casing.
- `docs/reviews/feat-872-ask-withdrawal/blast-radius.md` lists 82 "importers" for both route files and `email.ts` for `approval.ts` — substring matches on `route.ts` / `approval`. Harmless, but the file overstates the radius.
