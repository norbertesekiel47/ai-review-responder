## Appendix — NOT findings (out of this round's scope, or below the confidence bar)

- **Not in scope for this round — the standalone row's `aria-current` on non-matching Requests routes.** `Sidebar.tsx:196` passes `section="requests"`, so with the flag OFF the Review QR row renders `aria-current="page"` on any `/dashboard/requests/*` path, including `/dashboard/requests/qr/print/<id>` (a real, reachable route) and the two routes that `notFound()`. It is the same parent-lights-on-a-leaf semantics the pre-existing rows have (round 1's A1), so it is not new behaviour — but it is now attached to a row that claims to *be* a page rather than to head a section. Worth a decision, not a fix ticket.
- **`routed-tabs-breakpoint.test.ts:70-77` scans a fixed 4000-character window** (`consoleCss.slice(start, start + 4000)`) and then takes `body.split('@media')[1]`, so the window can run past the end of the media block it is checking. A future rule added within 4000 chars *after* an unrelated media query could fail this test with a message about breakpoints. Loud failure, not silent — noted, not filed.
- **`redirect()` in the new print page is a 307, not a 308** — same observation round 1 made about the parent redirect. Both files' comments call them "permanent". Practical impact on an authenticated noindexed route is near zero.
- **No 390px / 1440px screenshots on the branch.** The global design rule asks for them before approval, and finding **R1** is precisely the class of defect only a 1440px screenshot or a built-CSS read catches. The test suite is green and the band is still on screen.
