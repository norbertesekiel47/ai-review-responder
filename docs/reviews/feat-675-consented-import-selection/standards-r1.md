## Low-confidence appendix (style preferences / pre-existing — not findings)

- **Test `as any` harness convention** — `(sql as any).begin`, `logger as any`, `(call: any[])` predate this branch and are the file-local mock idiom; not lint-enforced. A typed `MockedSql` helper would be nice someday; out of scope here.
- **Bundled scenarios per `it`** — "pages until the target is met…" (Case A/B) and "does not report cap exhaustion…" ((i)/(ii)) each run two independent scenarios under one title, so a Case-B failure reports under Case A's name. Understood cause: intake-locked promised-test titles; nested `it`s under a shared `describe` title would preserve the gate while splitting failures.
- **Env mutation cleaned in `beforeEach`, not `afterEach`** (`ZernioBackfillWorker.test.ts:244-248`) — the last test to run can leak `ZERNIO_*` env into the file's teardown; benign under vitest per-file isolation, but an `afterEach` delete would be symmetrical.
- **`selectImportWindow` re-parses `createTime` per comparison** — filter + comparator + reduce each call `new Date(...).getTime()`; at n ≤ ~300 this is noise. A decorate-sort-undecorate would read slightly cleaner if the function ever grows.
- **`sqlReturnQueue` positional coupling** — every handler test depends on the handler's exact statement count/order (4 setup results). Established repo harness (`mock-sql` helper); F2's extraction is the real remedy.
- **Pre-existing, untouched**: `attempt as number` at the `handleZernioIngestError` call site; the two pre-existing `mkTaggedResult` copies at `zernio-ingest-shared.test.ts:199/322`; `worker/index.ts:218-221` stale comment (already logged as a standing plan note for the post-merge sweep).
