# Codex Adversarial Review

Target: branch diff against ae110dfd26ebef8fb66ea0fa0e6a2757d7ec04c1
Verdict: needs-attention

NO-SHIP: the same-version generation cache deterministically bypasses the freshness gate and can persist the exact stale draft this change is intended to prevent.

Findings:
- [critical] Same-version cache lets the replacement job persist the stale draft (worker/jobs/response-generation/persist.ts:122-148)
  The gate compares the current worker attempt's loaded hash with the current database hash, but it never binds `result.responseText` to that hash. Production caching uses only `(reviewId, version)` (`src/lib/costs/tracker.ts:55-56`) and the cached payload contains no content hash (`src/lib/responses/generator.ts:120-138,226-241`). Because content-change ingest deliberately enqueues the replacement at the same version (`src/lib/reviews/process-review.ts:352-372`), a stale H1 worker can cache its draft, ingest can commit H2, and the stale persist can skip; the replacement then loads H2 but receives the cached H1 draft. This gate sees H2 equal H2 and inserts the stale H1 response. The 24-hour cache is not cleared on review changes or gate skips, and the new integration test calls persistence with a fabricated result, bypassing this failure path.
  Recommendation: Include `loadedReviewContentHash` in the generation cache identity or stored payload and reject cache entries whose hash is missing or mismatched. Add an end-to-end worker test covering stale H1 cache creation, H2 content-change replacement at the same version, and persistence of newly generated H2 output only.

- Fix cache provenance before shipping ADR 0017.
- Add replacement-job coverage through generation/cache/persistence rather than testing persistence in isolation.
