## Non-actionable (observations, no fix demanded)

- **`moderation-runner.ts` gained module-scope side effects.** `const INJECTION_TARGETED = new Set(loadSafetyCorpus().map(...))` runs a `readFileSync` at import, and the file now statically imports `run-task.ts` and `safety-review.ts` (hence `cost-guard` → `tracker` → Redis cache module). Every client is lazily constructed today so nothing breaks, but the default corpus lane and the keyless unit suite now carry that graph, which sits slightly against `run.ts`'s "the offline default stays import-light" comment. Deferring the load (a lazy getter) would keep the claim literal.
- **`moderation_flagged` drafts now also carry `safety_review_unavailable`.** When the worker skips the check because moderation flagged, `safetyVerdict` is `null`, and the gate adds `safety_review_unavailable` alongside `moderation_flagged`. `AUTO_APPROVAL_BLOCK_PRECEDENCE` puts `moderation_flagged` first, so the Refusal ledger records the right code and the owner is never told "we could not check it" — but `blockReasons` (and the decision summary) assert a watchdog outage for a check that was deliberately, correctly skipped. `edge_cases[0]` predates D11's split and says only "the verdict passed to the gate is not-cleared". A `source: 'skipped'` verdict would read more honestly than `null`, at the cost of one more constructor.
- **`leaves the default corpus mode unchanged…` compares new code against new code.** `runModerationCorpus(CORPUS, cleanFn, 'test')` vs `…, {}` both run the post-change scorer, so the test cannot detect a change that affects both. The companion test at `moderation-corpus.test.ts:484` (exact `acceptance` key set, `total === 53`, safety ids absent from the shared file) is what actually pins the evidence; I verified byte-identity by reading the code rather than relying on either test. A `toMatchSnapshot` of `Object.keys(report.results[0])` would close the residual gap cheaply.
- **F1 has a cheap partial mitigation already available:** `effectivePolicy` is only readable inside the transaction, so a *policy-existence* pre-filter is not possible outside `sql.begin` — but the tier one is, and it removes the large majority of the wasted calls.
