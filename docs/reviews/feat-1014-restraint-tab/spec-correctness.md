## NON-ACTIONABLE APPENDIX

Observations below are either below the 80% confidence bar, out of this branch's contract, or judgement calls the owner may reasonably decline.

1. **`pairArchivedPeriods` is a second public export from `read.ts`.** `test_seams[0]` calls `getRefusalLog` "the read module's only public function". The extraction is deliberate (plan Task 4, and `read.test.ts` proves two cases the audit log cannot be made to produce), and nothing else imports it — but it is a contract field the deviations file does not record.
2. **`ReviewsContent` still loses `ReviewsTabs` during load and error.** D5/ST-2 describe the tab-bar inconsistency as "the bar vanished on one route and persisted on the other"; the fix was applied to the two Analytics routes only, and `ReviewsContent.tsx:31` passes no `beforeContent`. Out of #1014's contract, but the same defect on a sibling surface.
3. **`RestraintContent` derives account-vs-location from the client scope, not the payload.** `scope={currentScope === 'all' ? 'account' : 'location'}`. If a stale `rw_location_scope=all` cookie ever survived a `MULTI_LOCATION_ENABLED` flip-off, the server would return a *location* log while the tab printed the *account* sentence. The layout guards the cookie (`initialScope` only becomes `'all'` when the flag is on), so I could not construct a reachable path; `RestraintReport`'s own comment argues against the alternative (deriving from `archivedLocations !== null`) on separate grounds.
4. **`archivedFootnote` does not name the window.** "4 more from 2 archived locations are not shown." — the underlying count *is* window-bounded, but the sentence does not say so, and it sits beside a summary line that does. Not an all-time claim; possibly worth one clause.
5. **`AnalyticsContent`'s `SubscriptionUnavailableCard` branch renders no tab bar.** An inactive per-location account on `/dashboard/analytics` loses the route to Restraint. `user_visible_behavior[11]` only names the loading/error scaffold, so this is outside the contract.
6. **The Restraint route has no subscription branch of its own.** Unlike `AnalyticsContent`, `RestraintContent` never checks `perLocationActive`; a `cancelled` account with a live session would render the tab. E11 only requires that `past_due` renders, and `requireOwnerWithAccount` gates nothing further, so this matches the contract as written.
7. **"orders newest first within each category" is proven with one category.** The read's `ORDER BY r.occurred_at DESC, r.id DESC` is global and the live-DB case seeds three `unsafe_content` rows; the component's ordering case likewise uses a single category, and the multi-category case (3+2 rows) asserts grouping but not per-group order. The behaviour is correct by construction; the title is broader than either fixture.
8. **Dead CSS in `restraint.css`.** `.rst-group-link`, `.rst-row-ago` and `.rst-error-body` are defined but referenced by no component at HEAD. A standards concern, not a spec one.
9. **`account_audit_log` ordering ties.** `archivedPeriods` orders on `created_at ASC` only; two archival events in the same millisecond would pair non-deterministically. Not reachable in practice (archive refuses an archived location, and reactivate refuses an active one).
