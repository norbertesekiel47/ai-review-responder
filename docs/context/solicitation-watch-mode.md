## Solicitation (watch-mode) — locked 2026-07-23, ticket #534

- **Requests**: the owner-facing name of the Solicitation surface (`/dashboard/requests`) — the latest Solicitation batch as a funnel hero above its Spoilage report. `Solicitation` stays the internal/agent term (runs, tables, worker, flag) and `Ask` keeps its per-candidate meaning; only the screen, the nav row and the route say "Requests". *(coined in ticket #544)*
- **Solicitation batch** (a "batch"): one evaluated cohort of review-solicitation candidates — the subject of a `solicitation_batch` parent run. Its lifecycle (**built → reviewed → expired**) is owned by the batch domain entity, never by the run spine: `built` is the fact the run completed, `reviewed` is the owner opening it, `expired` is derived at read time from build age (a code-constant window, not stored). **`expired` is NOT implemented** — watch-mode has no staleness threshold and no expiry banner: the Requests screen renders a relative build time ("Built 3 days ago") and never presents a batch as out of date. The derived-expiry constant lands in send-mode, where it actually gates something (blocking sends from stale batches — `docs/superpowers/specs/2026-07-23-run-engine-executor-shape.md:87-90`). Supersedes the May reference design's "solicitation list". *(coined in the #534 executor-shape grilling; expiry scoped to send-mode in #544)*
- **Ask**: one per-candidate decision inside a batch — **send | withhold**, with a closed withhold-reason enum and the evidence that justifies it. The ask row is the authoritative decision record (it outlives run archival); the per-candidate child run is attribution. In watch-mode "send" means *would send* — nothing is transmitted. "Outreach" is reserved for send-mode's actual sends. *(coined in the #534 executor-shape grilling)*
- **Logical fan-out**: the watch-mode executor discipline — one worker job creates, steps, and completes every per-candidate child run inline under the batch parent (real parent/child graph, no per-candidate jobs, no join primitive). *Physical* fan-out (throttled spawn, `wait_for_children`, per-child retry) is send-mode machinery, built only when children genuinely run asynchronously. *(coined in the #534 executor-shape grilling; ADR 0011)*
- **Batch candidate window**: the bounded cohort a Solicitation batch evaluates from the whole accumulated location pool — never merely the upload that triggered it. Windows rotate by least-recently-evaluated ask so pools larger than one window are not stranded; this evaluation history schedules work but is not simulated contact history. *(sharpened in the #543 executor grilling)*
- **Simulated contact history**: the prior would-have-sent inclusions used by watch-mode's `over_contacted` gate. Only asks with `status='send'` enter this history; a `velocity_banked` ask is an evaluated withhold and never starts the minimum-gap clock. *(sharpened in the #543 executor grilling)*
