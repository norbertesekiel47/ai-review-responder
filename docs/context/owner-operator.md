## Owner Operator — coined 2026-09-11, Run A intake

The conversational surface an owner uses to configure RepWorth by talking. Spec of record: `docs/roadmap/2026-09-11-owner-operator/README.md`. Run A builds the turn pipeline and the voice-scope proposal; Apply, Decline, receipts and the screen are Run B, so every term below describes something **stored and read back**, never something that takes effect.

- **Operator turn**: one owner message and the single model reply it earns — an `agent_turns` row carrying `owner_text`, the stored `location_id`, a `sequence` within its conversation, and a lifecycle `accepted → running → completed | failed`. **The turn, not the browser, owns the target**: the location is frozen at POST, so moving the selector afterwards retargets nothing. Idempotency is the account-scoped `(account_id, client_turn_key)` unique — a re-POST of the same key and payload returns the original ids and writes no second row; a different payload under that key is a 409, and `text` is compared verbatim. _Avoid_: message, chat turn, prompt, request. *(coined in the Run A intake, 2026-09-11)*

- **Turn claim**: the `UPDATE agent_turns SET status='running', attempt = attempt+1, attempt_token = <uuid>, claimed_at = NOW()` that one dispatch wins and every other one loses, bounded by a 180-second lease. **Zero rows returned is a normal outcome, not an error** — a live lease is held elsewhere, so the losing attempt exits without touching the outbox row, which belongs to the winner — unless the turn is already terminal, when it closes the row nobody else will. The claim is what makes the watchdog's re-dispatch safe. _Avoid_: lock, reservation, job lock, lease acquisition. *(coined in the Run A intake, 2026-09-11)*

- **Fenced completion**: the one transaction that ends a turn — the terminal `UPDATE … WHERE id = $1 AND account_id = $2 AND attempt_token = $token`, the proposal inserts, the supersession, the unsupported inserts and `markOutboxCompletedIfOwned`, all or nothing. **A zero-row fenced UPDATE means the lease was lost: discard the model output and exit** — do not retry, do not fail the turn, do not touch the outbox row; the attempt that owns the lease will. Both terminal transitions are fenced this way; only the flag-off and exhaustion paths write unfenced. _Avoid_: commit, finalize, atomic write. *(coined in the Run A intake, 2026-09-11)*

- **Context snapshot**: the bounded, server-built object the model is allowed to see — recent finished turns, pending **Proposals**, **Operating rules**, the tier-filtered catalog, the location list, star-band and posted counts, and the stored voice facts. **It carries no review text, no response text and no reviewer name, ever** — `sample_responses` is EXCLUDED for that reason, which is why its `facts` is a four-field projection rather than the voice writer's own type, and why an earlier turn's `owner_text` is re-scrubbed on the way in. That is a type-level property rather than a filter: the snapshot has no field those could occupy. Counts reach the owner only through it, so a model-invented number is a validation failure. _Avoid_: context, prompt context, model input, payload. *(coined in the Run A intake, 2026-09-11)*

- **Reply segment**: one element of the ordered list a reply is made of. The model may emit five kinds — `text`, `status_ref`, `proposal_ref`, `question`, `scope_check` — and never returns prose paragraphs. **What is STORED is a narrower, server-owned union**: a `status_ref` supplies only a metric NAME and is replaced at **Fenced completion** by a `status` segment carrying the value, its reporting period and the instant it was read, and a scrubbed message gains a `server_notice`. Both are stored and never model-emitted, which is what makes a number on screen a frozen read rather than a claim, and what stops a refresh repainting a week-old sentence with today's count. A `text` segment with a digit next to a metric word, or a completion claim ("applied", "updated", "now active"), fails validation. _Avoid_: message part, block, chunk, response section. *(coined in the Run A intake, 2026-09-11)*

- **Proposal**: a stored `agent_proposals` row describing one catalog operation the owner has not yet approved — operation, scope, input, full-state `before` and `after`, rationale, a `label_kind` of `rule` or `fact`, and a status in `pending | applied | stale | rejected | failed | superseded`. **A Proposal is never an action**: in Run A no executor exists, nothing reaches Google and no `auto_approval_policies` row moves. A later turn proposing the same operation and scope marks the earlier pending row `superseded` with `superseded_by` set. _Avoid_: suggestion, recommendation, pending change, action. *(coined in the Run A intake, 2026-09-11)*

- **Requested capability**: an `agent_unsupported_requests` row — the normalized text of something the owner asked for that RepWorth cannot do, with its context. **A separate kind, not a Proposal with no button**: the two return under separate response keys (`proposals`, `unsupported`), so a renderer can never grow an Apply affordance onto one. It records demand; it does not decide the roadmap. _Avoid_: unsupported proposal, feature request, backlog item, no-op card. *(coined in the Run A intake, 2026-09-11)*

- **Contract version**: the catalog's own version for one operation's input shape and effect semantics, stored on the **Proposal** at preparation time. **It is not freshness** — it answers "does this code still mean what the Proposal meant?", and a mismatch is refused before any lock or read. Run A registers every proposable operation at `contract_version: 1`. _Avoid_: schema version, catalog version, proposal version. *(coined in the Run A intake, 2026-09-11)*

- **Version token**: the settings-freshness stamp recorded as `prepared_version_token` — for voice scope, `{ businessId, updatedAt }` read from `businesses.updated_at`. **It records row identity and existence, not only a timestamp**, so an auto-approval token reading `'absent'` matches only while that row is still absent. Run A stores it; Run B compares it. _Avoid_: etag, timestamp, freshness check, revision. *(coined in the Run A intake, 2026-09-11)*

- **Operating rules**: the effective configuration of one scope as the owner would state it — the auto-approval threshold, veto window and daily cap from `getAutoApprovalSettings`, plus the voice config. **Effective, not stored**: a location with no override row still has Operating rules, inherited from the account default, and a **Proposal**'s `before`/`after` shows that whole effective state rather than the single named dial. _Avoid_: settings, policy, config, dials. *(coined in the Run A intake, 2026-09-11)*

- **Pasted-review scrub**: the server-side replacement of a pasted review block in an owner message with `[review text removed]` before the **Context snapshot** or the prompt is built. **The stored `owner_text` is never modified** — the scrub is a read-path transform, so the owner's own record of what they typed stays intact. A scrubbed message earns a fixed, stored **Reply segment**; no fact is extracted from pasted text. _Avoid_: sanitize, redact, filter, strip. *(coined in the Run A intake, 2026-09-11)*

- **Operator flag**: `OWNER_OPERATOR_ENABLED`, server-only and default off, read through `readFlag` by `ownerOperatorEnabled()`. **Off means the surface does not exist**: the routes 404 `operator_disabled` before any write, and a dispatched `agent_turn` job fails its turn with that reason and completes its outbox row without loading tenant context. No `NEXT_PUBLIC_*` companion (invariant #13). _Avoid_: operator toggle, feature switch, kill switch. *(coined in the Run A intake, 2026-09-11)*

- **Receipt**: the server-written `agent_proposals.receipt` JSONB — operation, scope, the `before` the card showed, the `after` that actually committed, `differsFromPreview`, `effectiveNow`, what it affects, what remains blocked, `appliedAt`, the actor, the VERBATIM `owner_text` of the turn that produced the **Proposal**, the turn id as correlation id, and the **Version token** on both sides of the write. **Written in the SAME transaction as the mutation, and only there**: there is no committed mutation without a Receipt and no Receipt without a committed mutation, and the client supplies no field of it. A repeat Apply returns the stored one and executes nothing. _Avoid_: confirmation, result, audit entry, changelog. *(coined in the Run B intake, 2026-09-12)*

- **Refresh plan**: the action a `stale` or `contract_changed` **Proposal** card offers — **a new Operator turn posted from that Proposal's ORIGINAL `owner_text`**, not a retry of the Apply. The settings moved (or the code did), so the plan must be prepared again against the state that exists now; the owner's own words are the only input still true. It creates a fresh **Proposal**; it never revives the stale one. _Avoid_: retry, re-apply, regenerate, refresh. *(coined in the Run B intake, 2026-09-12)*
