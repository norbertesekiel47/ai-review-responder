## Restraint policy — locked 2026-07-23, ticket #533

- **Restraint policy**: the deterministic, sentiment-blind rule set that decides send vs withhold for each Solicitation candidate — the refusal logic is the product; everything else displays its decisions. No LLM in the decision path. *(coined in the §9 solicitation roadmap; locked in ticket #533)*
- **Withhold reason**: one code from the closed six-reason enum (`no_consent`, `suppressed`, `already_reviewed`, `stale_visit`, `over_contacted`, `velocity_banked`) explaining why a candidate was not asked. Every reason is sentiment-blind by construction; `recent_negative` is permanently rejected (ADR 0012). First-match precedence; one reason per withhold. **#1048 supplies `already_reviewed` from retained outreach attribution:** only an extant, non-deleted review with a recorded review date linked to earlier outreach for this contact at the same account/location qualifies. All retained attribution history is eligible; neither the 14-day attribution window nor the display window limits this read. Missing/deleted/undated review evidence abstains. This does not identify spontaneous reviewers and is not a never-ask-again guarantee. _Avoid_: refusal code, skip reason. *(locked in ticket #533)*
- **Freshness window**: the per-vertical day count beyond which a candidate's last visit is too stale for a genuine review ask (`stale_visit`). v1 is a hard window; learned decay curves are the future upgrade behind the same gate. *(locked in ticket #533)*
- **Vertical**: the coarse business-type bucket (`food_and_drink`, `retail`, `personal_care`, `fitness`, `medical_dental`, `automotive`, `home_services`, `other`) resolved deterministically from the owner-typed `businesses.category` text, falling back to `other`. *(coined in ticket #533)*
- **Velocity banking**: withholding an otherwise-eligible candidate solely because the batch cap is reached — banked most-recent-visit-first-kept, expected to return in a later batch. Volume shaping, not rejection. *(coined in ticket #533)*
- **Evidence snapshot**: the immutable, per-withhold record (typed per reason, `policy_version` + `decided_at` envelope, candidate referenced by ID only, never duplicated PII, never a star rating) that makes every decision re-explainable without re-running the policy. *(locked in ticket #533)*
- **Spoilage report**: the batch-approval display of withheld candidates with their withhold reasons — the visible-restraint aha moment of watch-mode. *(coined in the §9 solicitation roadmap)*
