### Measurement limits

The completed-turn distribution measures `agent_turns.completed_at - created_at`; its denominator includes only valid completed samples. The independent submission ledger retains every actual browser attempt, including any failure without a durable turn. Planned attempts with no actual submission time do not count as submitted.

Per-turn model duration is unavailable from the current durable records. `tryRecordOperatorCost` in `src/lib/agents/operator/model-call.ts` records account, location, provider and latency, but no turn/outbox ID, and passes `responseId: null`. A successful fallback can include both providers in one duration, and an all-invalid structured call can repeat its whole-call duration across billed audit rows. The separate cost query therefore reports an unassigned audit-row distribution; it does not join by nearest timestamp, sum repeated durations, or claim per-turn model timing.

Final `job_outbox.dispatched_at` is the latest dispatch or heartbeat timestamp, because healthy predecessor waits refresh it in `releaseTurnClaim`. Its offset from creation is not first queue wait. `agent_turns.claimed_at` likewise holds only the latest surviving claim, and claim release decrements `attempt`; final rows cannot reconstruct every earlier claim. Retain periodic snapshots and exact correlated worker logs/BullMQ metadata before teardown, and report unavailable subphase timings explicitly. These limits do not change the end-to-end completed-turn percentile calculation.
